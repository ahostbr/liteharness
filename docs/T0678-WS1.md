## Pain Diagnosis

Normal mail must keep its existing addressee while an optional, live clerk receives routine traffic first. A second reader on the orchestrator's mailbox would recreate the historical race. The boundary is the writer, not a watcher.

## Composition Analysis

One pure route predicate per language, composed into the existing atomic maildir writers. Existing Python liveness functions moved unchanged; their ASTs compare identical to base 39d26a462f3998ae83b118673042768c174666b6. CLI aliases remain. TS reuses `ipc/session-owner.ts` bounded psutil probe and live-PID check, with Python's 43200-second freshness, zero creation-time slack and later-registration supersession. Discovery's 600-second/5-second-slack policy is deliberately not substituted. Unknown creation-time probe retains Python's leniency.

## Refactoring

Before: CLI and app always write to the requested address. After: valid enabled config + eligible addressee + live clerk writes to clerk with `original_to`; otherwise the message shape/address remains unchanged. Direct, configured Ryan sources, clerk-origin and already-forwarded messages bypass routing. No reader changed. TS first calls the same pure rule with a true liveness callback to skip expensive probes on bypasses, then with the bounded probe result; there is no second routing policy.
